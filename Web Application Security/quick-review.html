مراجعة سريعة — أمن تطبيقات الويب

الجملة الذهبية: تطبيق الويب يستقبل طلبات HTTP من عالم غير موثوق. الأمن يعني منع الطلبات والإدخالات من التحول إلى أوامر خطيرة أو وصول غير مصرح.

7) خطوات الهجوم حسب الشرائح

  1. Gather intelligence: ports, errors, infrastructure leaks
  2. Match information with known defects
  3. Attack weak spots using input validation problems

9) Injection

Injection = بيانات غير موثوقة تُرسل إلى Interpreter فيتعامل معها كتعليمات.
النوعالمفسرالدفاع
Command InjectionShell/OSتجنب shell، allowlist، escaping، أقل صلاحيات
SQL InjectionDatabase SQLPrepared statements، validation، least privilege
XSSBrowser HTML/JSOutput encoding، CSP، HttpOnly cookies

10) SQL Injection

يحدث عندما يركب التطبيق إدخال المستخدم داخل SQL فيغير معنى الاستعلام.
Tautologies: شرط صحيح دائماً
ORDER BY probing: معرفة عدد الأعمدة
UNION: دمج استعلام آخر
Error leakage: أخطاء تكشف الداخل
Blind SQLi: استنتاج من السلوك/التأخير
Second-order: يخزن الآن ويؤثر لاحقاً

11) XSS

النوعالمعنىالأخطر؟
Reflected XSSرابط/طلب يحمل سكربت يعكسه الخادميحتاج غالباً نقر رابط
Stored XSSسكربت يخزن في DB/الخادم ويعرض للزوارغالباً أخطر لأنه يصيب الزوار تلقائياً
XSS قد يؤدي إلى سرقة Session Cookie أو تنفيذ أفعال باسم المستخدم.

12) Sanitization

Sanitizing Is Not Easy: حذف <script> فقط غير كافٍ بسبب الترميزات والسياقات المختلفة.
السياقالدفاع
SQLParameterized queries
HTMLHTML output encoding
JavaScriptتجنب إدخال غير موثوق + encoding مناسب
URLURL encoding + تحقق من الرابط
Shellتجنب shell أو allowlist + escaping

13) كيف تحل سؤال سيناريو؟

  1. حدد الطبقة: Browser/HTTP/App/DB/Cookie.
  2. حدد الثقة الخاطئة: إدخال/جلسة/تفويض/إعداد.
  3. حدد الهجوم: SQLi/XSS/Command Injection/Broken Access Control.
  4. حدد التأثير: بيانات/جلسة/تنفيذ/سمعة.
  5. اكتب الدفاع المناسب.
