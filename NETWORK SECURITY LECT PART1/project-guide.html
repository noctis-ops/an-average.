دليل مشروع أمن الشبكات العملي — نسخة فردية واقعية

الخلاصة الصريحة: المشروع الكامل كما هو مكتوب يحتاج تحميلات كبيرة إذا لم تكن عندك مسبقاً: pfSense ISO، وربما Windows Server لـ NPS، وPacket Tracer، وربما Suricata packages. لكن يمكن إنجاز نسخة فردية مقبولة بأقل خسارة بيانات إذا استخدمت الموجود عندك، واستخدمت بدائل خفيفة، ووثقت في التقرير أنك نفذته وحدك ضمن الإمكانات.

العودة للشرح النظري

2) هل يمكن إنجازه بدون استهلاك بيانات كبير؟

قراري لك: لا تنزل Windows Server من الإنترنت الآن. إذا الوقت غداً، ركز على: Packet Tracer routers + pfSense إن كان ISO متوفر + تقرير قوي + لقطات شاشة. استخدم Kali الموجود عندك لـ Nmap/Wireshark. Radius/NPS وSuricata إذا ما قدرت تحملها، اعمل بديل ووضّح للدكتور أنك نفذت فردياً وبموارد محدودة.

3) Minimal Viable Project — نسخة فردية قابلة للتسليم

  1. ارسم التوبولوجي كما في الملف، وضع IP plan خاص بك.
  2. نفذ جزء Cisco Packet Tracer كاملاً لأنه لا يحتاج تحميلات كبيرة إذا البرنامج موجود.
  3. نفذ pfSense إذا ISO متوفر؛ لو غير متوفر، ضع تصميم وقواعد screenshots من Packet Tracer ACL كبديل جزئي واذكر السبب.
  4. استخدم Kali كـ Client 2 لتشغيل Nmap وWireshark داخل lab.
  5. استخدم Packet Tracer Server كـ AAA/Syslog/NTP بدل Windows Server إذا الوقت/البيانات لا تسمح.
  6. اعمل Suricata فقط إذا مثبت أو يمكن تثبيته بسرعة؛ وإلا قدم Wireshark captures وتحليل IDS concept.

6) pfSense مختصر

  1. أنشئ VM pfSense بواجهتين: WAN وLAN.
  2. WAN على شبكة Client1، LAN على شبكة السويتش الداخلي.
  3. من Web GUI: System → User Manager → Add user باسمك واجعله admin.
  4. Firewall → Rules → WAN: أضف rule block ICMP من Client1 إلى Client2.
  5. Firewall → Rules → WAN: أضف rule block TCP 443 من Client1 إلى This Firewall/WAN address.
  6. اختبر ping وhttps ثم افتح Status → System Logs → Firewall.
  7. Hardening: غيّر كلمة admin، عطّل الخدمات غير الضرورية، فعّل HTTPS للواجهة، لا تسمح للإدارة من WAN إلا للحاجة.

7) Nmap وWireshark

Nmap من Kali/Client2

nmap -sV 192.168.50.10
nmap -Pn -p 1-1000 192.168.50.10

اكتب في التقرير: المنافذ المفتوحة، الخدمة، هل يجب أن تكون مفتوحة؟ وكيف تمنعها firewall policies؟

Wireshark

  1. ابدأ capture على واجهة Client1 أو Client2.
  2. نفذ ping أو HTTP test.
  3. سجل: Protocol، Source، Destination، هل البيانات encrypted؟
  4. اربط النتيجة: إذا ICMP blocked ستشاهد محاولات أو لا ترى reply.

8) Suricata إذا أمكن

sudo apt update
sudo apt install suricata
sudo suricata -i eth0
sudo tail -f /var/log/suricata/fast.log

Custom rule مثال دفاعي للكشف عن ICMP داخل lab:

alert icmp any any -> any any (msg:"LAB ICMP detected"; sid:1000001; rev:1;)
إذا لم تستطع تثبيت Suricata بسبب الإنترنت، لا تضيع اليوم كله. وثق في التقرير أنك نفذت تحليل Wireshark/Nmap وقدمت تصميم IDS/IPS ومكان وضع Suricata وقاعدة custom rule كمقترح.

9) قالب تقرير جاهز

  1. Cover page: اسمك، المادة، التاريخ.
  2. Topology diagram + IP addressing table.
  3. شرح وظيفة كل مكون.
  4. pfSense configuration screenshots: interfaces، user، rules، logs.
  5. Packet Tracer screenshots: routers connectivity، SSH، login block، syslog، NTP، port security، CLI views.
  6. AAA/RADIUS: لقطة إعداد أو بديل Packet Tracer/FreeRADIUS مع شرح.
  7. Syslog: ثلاث أحداث أمنية.
  8. Suricata/Wireshark/Nmap: نتائج وتحليل.
  9. Potential attacks: scanning، spoofing، password attacks، DoS، malware.
  10. Recommendations: strong passwords، SSH only، ACLs، firewall least privilege، logging، NTP، IDS/IPS tuning، backups.
  11. Limitations: نفذت المشروع فردياً وبموارد محدودة، لذلك استخدمت بدائل حيث يتطلب الأصل Windows Server أو تحميلات كبيرة.

10) ماذا تقول للدكتور لو ناقشك؟

“الدكتور، نفذت المشروع بشكل فردي لأن ظروفي لم تسمح بفريق. التزمت بالتوبولوجي والفكرة الأمنية: Firewall rules، Router hardening، AAA، NTP، Syslog، IDS/IPS analysis، Nmap/Wireshark. في جزء Windows NPS/Suricata إذا لم تسمح الموارد، وثقت البديل وشرحت كيف سيتم تطبيقه في بيئة كاملة.”
